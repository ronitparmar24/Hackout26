# Carbon-Aware Supply Chain Dashboard

## Problem

Companies need to report Scope 3 (supply chain) emissions but have no way to trace carbon impact across multi-tier suppliers — data is scattered, manual, and unauditable.

## What we're building, in plain terms

A company uploads a CSV of their suppliers (electricity used, transport distance, material type/quantity per supplier). We calculate how much CO2 each supplier is responsible for, automatically flag suppliers polluting way more than similar ones, group suppliers by pollution pattern, and suggest lower-emission suppliers to switch to. They get a dashboard, a downloadable PDF audit report, and a CSV of the full enriched data.

**Users:** corporate sustainability teams, supply chain managers, ESG auditors.

## Where the data comes from

- **Emission factors** — the multipliers used in the math — are hardcoded from official government sources, not parsed live from spreadsheets (those files have hundreds of rows we don't need). See `emission_factors.py` below for the exact ~10 values used and where each came from.
- **Demo input data** — synthetic CSV of ~60-80 fake suppliers, generated by a script (Faker + numpy), since we won't have a real company's data for the demo.

## Where ML is actually used (and where it isn't)

| Task | Is it ML? |
|---|---|
| Checking if a field is empty | No — plain code (`if value is null`) |
| Guessing a missing number based on similar suppliers | **Yes** — regression model |
| Adding up energy + transport + material into a total | No — plain formula |
| Spotting a supplier whose emissions are way outside normal for its peer group | **Yes** — Isolation Forest (anomaly detection) |
| Grouping suppliers into pollution-pattern buckets | **Yes** — KMeans (clustering) |
| Suggesting a similar-but-cleaner supplier to switch to | **Yes** — cosine similarity search |

## Features

1. CSV upload & parsing
2. Missing-data estimation (regression model)
3. Base emission calculation (formulas, not ML)
4. Anomaly detection (Isolation Forest)
5. Supplier clustering (KMeans)
6. Circular sourcing recommendations (cosine similarity)
7. Interactive dashboard (table, bar chart, tree view, filters)
8. PDF report export
9. CSV export (enriched data)
10. Run history (stored in Supabase Postgres)

## Supabase PostgreSQL Schema

```sql
-- RUNS: one row per CSV upload
create table runs (
  id uuid primary key default gen_random_uuid(),
  created_at timestamptz not null default now(),
  filename text not null,
  total_suppliers int,
  total_emissions numeric,
  status text not null default 'processing' check (status in ('processing','done','failed'))
);

-- SUPPLIERS: raw input + calculated output in one row (1:1, no reason to split)
create table suppliers (
  id uuid primary key default gen_random_uuid(),
  run_id uuid not null references runs(id) on delete cascade,

  -- raw input
  supplier_name text not null,
  tier text not null check (tier in ('Tier 1','Tier 2','Tier 3')),
  region text,
  energy_kwh numeric check (energy_kwh >= 0),
  energy_kwh_estimated boolean not null default false,
  transport_km numeric check (transport_km >= 0),
  transport_km_estimated boolean not null default false,
  transport_mode text check (transport_mode in ('Road','Rail','Sea','Air')),
  material_type text not null,
  material_qty numeric check (material_qty >= 0),

  -- calculated output
  energy_emissions numeric,
  transport_emissions numeric,
  material_emissions numeric,
  total_emissions numeric,
  is_anomaly boolean not null default false,
  cluster_label int
);

-- RECOMMENDATIONS: suggested lower-emission swap for a given supplier
create table recommendations (
  id uuid primary key default gen_random_uuid(),
  supplier_id uuid not null references suppliers(id) on delete cascade,
  recommended_supplier_id uuid not null references suppliers(id) on delete cascade,
  similarity_score numeric not null check (similarity_score between 0 and 1),
  emissions_reduction_pct numeric
);

-- Indexes for the lookups the dashboard actually does
create index idx_suppliers_run_id on suppliers(run_id);
create index idx_suppliers_total_emissions on suppliers(total_emissions desc);
create index idx_recommendations_supplier_id on recommendations(supplier_id);
```

### Flow

1. User uploads CSV → `POST /api/upload`
2. Pandas parses + validates columns
3. Missing `energy_kwh` / `transport_km` → filled by the regression model, flagged as estimated
4. Base emissions calculated per row using `emission_factors.py` (formula, not ML) — transport factor is per tonne-km, so `transport_km * material_qty * factor`
5. Isolation Forest flags anomalies across the batch
6. KMeans assigns each supplier a cluster label
7. Cosine similarity generates recommendations for high-impact suppliers
8. Everything written to Supabase, tagged with a `run_id`
9. JSON response → frontend renders dashboard
10. `GET /api/export/csv/{run_id}` and `GET /api/export/pdf/{run_id}` pull from Supabase and generate the export on demand

### API endpoints

- `POST /api/upload`
- `GET /api/runs/{run_id}`
- `GET /api/export/csv/{run_id}`
- `GET /api/export/pdf/{run_id}`
